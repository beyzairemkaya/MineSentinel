# Live Demonstration Scenario & Validation Protocol

This document outlines the end-to-end operational test procedures used to validate the **MineSentinel** platform during live evaluation. The scenario demonstrates how the system transitions from nominal baseline monitoring to edge hazard alerts, automated ML classification, and LLM-driven emergency incident reporting.

---

## 1. Test Setup & Pre-Flight Checks

Before initiating the live demo, verify the following services and hardware links:

| Component | Port / Interface | Health Indicator |
| :--- | :--- | :--- |
| **ESP32 Edge Device** | USB Serial / 115200 baud | Wi-Fi connected, I2C (`0x68`) initialized |
| **FastAPI Core** | `http://localhost:8000` | Swagger UI accessible at `/docs` |
| **Streamlit Dashboard**| `http://localhost:8501` | Live telemetry graphs streaming |
| **Groq API** | HTTPS / Outbound | Valid API key configured in `.env` |

---

## 2. Step-by-Step Demonstration Script

### Stage 1: Nominal Monitoring (Baseline)
* **Action:** The device rests stationary on the flat demo surface in ambient air.
* **Observed Metrics:**
  * Gas PPM: $\approx 150 - 220\text{ PPM}$
  * Acceleration: $\approx 0.98g - 1.02g$ (Earth gravity baseline)
  * Hazard Duration: $0\text{ seconds}$
* **System State:**
  * Edge Alarm (Buzzer/LED): **OFF**
  * Risk Engine Score: $< 30.0$
  * ML Classifier Output: `LOW` (Confidence $\ge 0.90$)
  * Isolation Forest: Non-anomalous (`False`)
  * UI Display: Green status indicators, steady telemetry line chart.

---

### Stage 2: Gas Influx Simulation and Edge Warning

#### Synthetic Telemetry Injection

**Action:** Inject a controlled synthetic telemetry payload simulating an atmospheric methane or toxic gas surge. Use either the test harness script (`scripts/generate_sample_data.py`) or send a direct HTTP request to the telemetry ingestion endpoint:

```bash
curl -X POST http://localhost:8000/api/telemetry \
  -H "Content-Type: application/json" \
  -d '{
    "gas_ppm": 550.0,
    "accel_g": 1.02,
    "duration_sec": 4.0,
    "miner_id": "MINER-01",
    "zone": "Shaft-7B"
  }'
```

> **Alternative hardware method:** When demonstrating the physical ESP32 prototype, send the `SIM_GAS_SPIKE` command through the Serial Monitor at `115200` baud. This invokes the firmware's internal simulation routine without releasing pressurized or combustible gas in the laboratory environment.

#### Observed Metrics

* **Gas concentration:** Rises to \(550\ \text{ppm}\)
* **Acceleration:** Remains approximately \(1.0g\)
* **Hazard duration:** Increases from \(1\ \text{s}\) to \(4\ \text{s}\)

#### Expected System Response

* **Edge alarm:** The hardware LED flashes and the local warning buzzer activates.
* **Risk engine:** The calculated risk score transitions into the \(40.0\text{–}65.0\) range.
* **ML classifier:** Returns `MEDIUM`.
* **Dashboard:** The telemetry graph displays a sharp gas spike, and the alert indicator transitions to yellow or orange.


---

### Stage 3: Severe Impact & Man-Down Immobility (Emergency Trigger)
* **Action:** Tap/shake the sensor assembly sharply ($> 3.0g$ impact) to simulate a tunnel roof rockfall or structural collapse, then immediately place it completely motionless on the table for $> 10$ seconds to simulate worker immobility.
* **Observed Metrics:**
  * Impact Peak: Accel $> 3.5g$ (clipped in mathematical engine)
  * Immobility Phase: $|accel - 1.0| \le 0.08$ with persistent hazard timer ($\ge 10\text{s}$)
* **System State:**
  * Edge Alarm: Continuous critical audio/visual alarm pattern.
  * Risk Engine Score: Hard floor rule locks score to $\ge 75.0$.
  * ML Classifier Output: `CRITICAL` (High confidence).
  * FastAPI Pipeline: Triggers asynchronous background task for Groq LLM.

---

### Stage 4: Automated Incident Generation & UI Archive
* **Action:** Observe the Streamlit web dashboard without refreshing.
* **System State:**
  * Red high-priority critical warning banner occupies the top viewport.
  * Within 2–4 seconds, the **Incident Archive** expands with a structured incident response generated by Groq.
  * **Report Contents Verified:**
    1. Incident timestamp and miner ID (`MINER-01`).
    2. Estimated hazard vector (toxic atmospheric concentration + trauma shock).
    3. Actionable extraction protocol for the rescue team.

---

## 3. Expected Failure Modes & Handled Edge Cases

* **Network Dropout:** If local Wi-Fi degrades, local hardware alarms (Buzzer/LED) continue operating autonomously at the edge.
* **Sensor Saturation:** Acceleration spikes exceeding mechanical limits are clipped to $1.0$ in normalization to prevent risk calculation overflow.
* **Asynchronous Resilience:** Emergency LLM generation runs in a background thread; standard HTTP $200\text{ OK}$ telemetry ingestion is never blocked.
